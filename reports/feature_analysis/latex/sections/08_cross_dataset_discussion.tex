\section{跨数据集讨论}

\subsection{RUL 跨数据集对比}

RUL 是两个数据集中最一致的任务。

XJTU-SY 与 PHM2012 都支持 amplitude / energy-like time-domain features。

XJTU-SY 中，\feature{mag__time__mean}、\feature{mag__time__mean_abs}、\feature{mag__time__std} 是最终 A 级。

PHM2012 中，\feature{h__time__mean_abs}、\feature{mag__time__mean}、\feature{mag__time__mean_abs} 是 A 级。

这说明不同数据集的通道偏好不同，但退化信号的共同形态一致：振动幅值、能量和离散度随寿命推进发生变化。

XJTU-SY 的 RUL 更需要跨工况检查。

主划分中 horizontal 和 magnitude 都很强。

跨工况后 vertical/magnitude amplitude 的稳定性更突出。

PHM2012 official split 中 horizontal amplitude 更一致。

因此下游 RUL baseline 可以共享一个 amplitude compact subset，但在解释时要区分 dataset-specific channel preference。

\subsection{Health State 跨数据集对比}

Health State 在两个数据集上都是 amplitude-driven。

区别在于通道稳定性。

XJTU-SY main split 中 horizontal amplitude 很强。

但是 cross-condition 检查后，magnitude features 更适合作为 robust mainline。

PHM2012 official split 中 horizontal amplitude family 更强。

\feature{h__time__mean_abs}、\feature{h__time__std}、\feature{h__time__rms} 形成 PHM2012 的 A 级组合。

这个差异对 baseline 很重要。

如果把 PHM2012 的 horizontal 结论直接迁移到 XJTU-SY cross-condition，可能高估模型泛化。

更安全的做法是：XJTU-SY Health State baseline 优先使用 magnitude amplitude，PHM2012 Health State baseline 优先使用 horizontal amplitude。

\subsection{Early Fault 跨数据集对比}

Early Fault 是跨数据集差异最大的任务。

PHM2012 中，Early Fault 比较稳定地支持 horizontal/magnitude amplitude。

XJTU-SY 中，Early Fault 明显工况敏感。

Step H 总结为：

\begin{itemize}[leftmargin=2em]
  \item C1: spectral entropy 更显眼；
  \item C2: peak-to-peak / shock-like 特征更显眼；
  \item C3: horizontal amplitude 更显眼。
\end{itemize}

Step I 又进一步说明，cross-condition 中一些 spectral entropy 特征在 train 工况强，但不能直接升级为全局主线。

因此，Early Fault 的最终策略必须 dataset-specific。

PHM2012 可使用 amplitude mainline。

XJTU-SY 只能把 amplitude 作为安全主线，把 spectral/shock/horizontal 条件信号作为 C 级或 ablation 候选。

\subsection{tsfresh 对比}

tsfresh 在两个数据集上的结论不同，但最终决策一致。

XJTU-SY 的 full-size \config{manual_tsfresh_basic} 被阻塞。

这个结果是工程瓶颈，不是算法性能结论。

报告不能写成“tsfresh 对 XJTU 无用”。

更准确的表述是：当前 backend 不适合 full-size XJTU-SY raw-signal tsfresh extraction。

PHM2012 的 \config{manual_tsfresh_basic} 成功运行。

但 top \feature{tsfresh__} 特征主要是 RMS、standard deviation、variance、maximum、absolute maximum。

它们重复 \config{manual_basic} 已有统计量。

因此 PHM2012 的结果也不足以把 tsfresh 纳入当前主线。

后续若做 tsfresh，应满足两个条件：

\begin{itemize}[leftmargin=2em]
  \item 有 memory-aware backend，避免一次构造超大 long-format 表；
  \item 有 gain evaluation，证明新增特征 family 带来泛化或解释增益。
\end{itemize}

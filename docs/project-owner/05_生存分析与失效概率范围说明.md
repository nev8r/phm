# 生存分析与失效概率范围说明

本项目的核心交付是工业轴承 RUL 剩余寿命预测。生存分析与失效概率属于预测性维护扩展能力，当前代码保留基础接口，但不作为结题主验收路线。

## 1. 为什么需要单独说明

项目目标中包含“失效概率与生存概率分析”。如果不说明范围，评审可能会误以为结题主线应完整覆盖 Kaplan-Meier、Cox、RSF 等生存分析实验。当前实际情况是：

- RUL 数据加载、特征、模型、训练、指标和论文复现已经形成闭环；
- 生存分析模块已有基础服务类；
- 但生存分析没有像 RUL 论文复现一样完成大规模实验和答辩主线展示。

因此，正式口径应是：本项目保留生存分析扩展接口，结题主验收集中在 RUL 回归预测。

## 2. 生存分析输入语义

生存分析通常需要 `(duration, event)`：

| 字段 | 含义 |
| --- | --- |
| `duration` | 观察到的运行时间 |
| `event` | 是否发生失效事件 |

在轴承 run-to-failure 数据中，完整寿命轴承可以构造失效事件；但对于 PHM2012 Test_set 这种截断数据，需要区分已知终止 RUL、截尾样本和官方 challenge 条目，不能简单把所有文件末尾都当作真实失效。

## 3. 当前代码能力

`survival/survival_model.py` 提供基础服务：

| 能力 | 当前定位 |
| --- | --- |
| Kaplan-Meier | 可用于估计总体生存曲线 |
| Cox proportional hazards | 可作为特征与风险关系的基础模型 |
| survival probability 输出 | 可为后续可视化和维护策略提供接口 |

这些能力说明系统架构预留了预测性维护扩展方向，但本轮没有把它作为与两篇 RUL 论文复现同等规格的实验任务。

## 4. 与 RUL 预测的关系

RUL 和生存分析关注的问题不同：

| 方向 | 主要问题 | 本项目状态 |
| --- | --- | --- |
| RUL 回归 | 当前状态下还剩多少寿命 | 主线，已完成训练、指标、论文复现 |
| 生存概率 | 在未来某时刻前仍未失效的概率 | 扩展接口，保留基础能力 |
| 失效概率 | 某时间窗口内失效风险有多高 | 扩展接口，未做主验收实验 |

答辩时应优先讲 RUL，因为它与现有数据图、特征序列、模型训练和论文复现直接对应。

## 5. 如果后续补强

如果后续要把生存分析提升为正式验收功能，应补充：

1. 明确每个数据集的 `duration` 和 `event` 构造规则。
2. 区分完整寿命、截尾样本和 challenge Test_set。
3. 增加 Kaplan-Meier 曲线和失效概率曲线图。
4. 增加 C-index、Brier Score 等生存分析指标。
5. 增加测试文件验证输入、输出和可视化。
6. 在 PPT 中新增一页作为扩展实验，而不是混入 RUL 指标页。

## 6. 正式文档推荐口径

建议使用如下表述：

> 系统在架构上保留失效概率与生存概率分析接口，当前结题主线聚焦 RUL 回归预测。生存分析模块可作为后续预测性维护扩展方向，尚未作为本轮论文复现和课程主验收任务展开。

避免使用如下表述：

- “系统已达到生产环境级别的失效概率预测能力。”
- “生存分析结果已与 RUL 模型同等充分验证。”
- “PHM2012 Test_set 末尾即真实失效点。”
